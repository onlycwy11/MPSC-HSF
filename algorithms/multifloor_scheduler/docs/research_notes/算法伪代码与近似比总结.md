# 3DIMSTA 算法、近似比与复杂度统一版本

## 1. 统一问题和符号

设：

- `M=<V,E>`：室内三维拓扑地图，`|V|=V`；
- `R`：机器人集合，`|R|=R`；
- `T`：当前 batch 的任务集合，`|T|=M_t`；
- `Q=min(R,M_t)`：本 batch 最多可以完成的任务数；
- `P`：单个机器人-任务对需要检查的候选垂直通道路径数，包括可用电梯和楼梯；
- `H`：一条候选路径包含的时空事件数或边段数上界；
- `K`：冲突消解循环的实际迭代次数；
- `c_{ij}^p`：机器人 `r_i` 执行任务 `t_j` 采用候选路径 `p` 的无冲突基础耗时；
- `C_i`：机器人 `r_i` 当前路径和当前等待安排下的任务完成时间；
- `TW_i`：机器人 `r_i` 对电梯、窄通道等有限资源的占用时间窗。

一个任务只能分配给一个机器人，一个机器人在同一个 batch 内最多执行一个任务。分配关系确定后，冲突消解阶段只修改路径或等待时间，不修改机器人-任务匹配关系。

## 2. 总体算法结构

算法分为两个阶段：

1. **无冲突松弛阶段**：对每个可行的机器人-任务对计算最短候选路径，形成代价矩阵，用最小权二分图匹配得到 `A_ini`。
2. **冲突消解阶段**：固定 `A_ini`，反复检测时间窗冲突；对冲突机器人比较等待和改道的额外代价，保留代价增量最大的原路径，其余机器人采用代价最小的可行替代方案。

`A_ini` 不是原问题的可行最优解，而是去掉资源冲突约束后的松弛最优解。应使用代价记号：

$$
C_{\mathrm{relax}}=\operatorname{cost}(A_{\mathrm{ini}})
\le OPT.
$$

不能写成方案 `A_ini <= OPT`。

## 3. 阶段一：初始分配伪代码

```text
Algorithm InitialAssignment(M, R, T)
Input:
    map M=<V,E>
    robots R
    tasks T
Output:
    A_ini: robot-task matching with one candidate path per pair
    C_relax: total relaxed cost

1. Create an R x M_t cost matrix W and path table P_best.
2. For each robot r_i in R:
3.     For each task t_j in T:
4.         If type(r_i) != type(t_j):
5.             W[i,j] <- +infinity
6.             Continue.
7.         If r_i cannot reach S_j or G_j under map/type constraints:
8.             W[i,j] <- +infinity
9.             Continue.
10.        best <- +infinity
11.        For each candidate vertical route p in CandidateRoutes(r_i,t_j):
12.            path <- Dijkstra(M restricted to route p,
                                pos(r_i) -> S_j -> G_j)
13.            cost <- TravelTime(path), without inter-robot conflict waiting
14.            If cost < best:
15.                best <- cost
16.                P_best[i,j] <- path
17.        W[i,j] <- best
18.
19. A_ini <- MinimumWeightPerfectOrMaximumCardinalityMatching(W)
20. For every selected (r_i,t_j) in A_ini:
21.     attach P_best[i,j], base cost c_ij, and task completion time C_j.
22. C_relax <- sum of selected c_ij.
23. Return A_ini, C_relax.
```

如果允许任务未全部匹配，第19行应使用“最大基数、再最小权”的匹配；否则当前目标可能通过少分配任务而得到较小总成本。若要求当前 batch 全部完成，则使用完全匹配判定。

## 4. 阶段二：冲突消解伪代码

### 4.1 冲突检测约定

对每条容量有限的资源边或电梯 `e`，收集所有机器人在该资源上的占用区间：

$$
TW_i(e)=[s_i(e),f_i(e)].
$$

如果同一资源上同时占用的机器人数量超过容量，则产生一个冲突组。宽通道可根据通行规则放行；楼梯、窄走廊和电梯必须按容量和时间窗检查。

### 4.2 冲突消解算法

```text
Algorithm ResolveConflicts(M, A_ini, R, T, P)
Input:
    map M
    initial assignment A_ini
    current path/arrival information P
    maximum iteration count K_max
Output:
    A_final: conflict-free schedule if one is found

1. A <- A_ini
2. State <- BuildScheduleState(A)
3. C <- DetectConflictGroups(State)
4. iter <- 0
5.
6. While C is not empty and iter < K_max:
7.     iter <- iter + 1
8.     Select one conflict group c from C
9.     R_conf <- robots involved in c
10.
11.    For each robot r_i in R_conf:
12.        current <- current assignment/path of r_i
13.        wait_option <- DelayUntilResourceIsAvailable(current, c, State)
14.        reroute_options <- EnumerateUnusedFeasibleRoutes(M, r_i, task(r_i))
15.        reroute_option <- argmin cost among reroute_options
16.        alternative_i <- argmin{cost(wait_option), cost(reroute_option)}
17.        delta_i <- cost(alternative_i) - cost(current)
18.
19.    r_keep <- argmax(delta_i for r_i in R_conf)
20.    Keep current path and time window of r_keep.
21.    For every r_i in R_conf except r_keep:
22.        Replace its path/time window by alternative_i.
23.        Mark the selected route or waiting state as used.
24.
25.    State <- RebuildScheduleState(A)
26.    C <- DetectConflictGroups(State)
27.
28. If C is empty:
29.     Return A as A_final.
30. Else:
31.     Apply deterministic fallback scheduling:
32.     freeze robots in priority order and reserve their resources;
33.     plan every remaining robot around the frozen time-space obstacles.
34.     If a task has no feasible path before its deadline, report infeasible.
35.     Return the resulting schedule or infeasibility.
```

第19行的贪心选择有明确含义：如果当前组中必须保留一个机器人原路径，其余机器人改道，那么保留 `delta_i` 最大的机器人可以使当前组的即时增量

$$
\sum_{i\in R_{conf}\setminus\{r_{keep}\}}\Delta_i
$$

最小。

但是它只优化当前冲突组的即时增量，并不保证全局最优。PPT 中 A、B、C 的例子已经说明：一次冲突中增量最小的选择，可能导致后续二次冲突，最终总成本反而更高。

## 5. 终止性要求

如果机器人可以在不同迭代中反复使用同一条路径，算法可能出现循环。要得到可证明的终止性，至少需要满足一个条件：

1. 每个机器人对每个候选路径或等待状态最多使用一次；或
2. 每次迭代都把一个新的状态永久标记为已使用；或
3. 使用固定优先级冻结策略作为兜底，冻结后的机器人不再改变。

在每个机器人最多尝试 `P` 个候选状态的约束下，可以取

$$
K\le R P.
$$

因此 PPT 中的 `K=tR` 只有在 `t` 表示每个机器人最多尝试的垂直路径或候选状态，并且不允许回退时才成立。若允许路径反复切换，`K=tR` 不是自然成立的最坏情况上界。

## 6. 初始分配阶段的时间复杂度

对一个机器人-任务对，若需要检查 `P` 条候选垂直路线，每次 Dijkstra 使用邻接矩阵实现，时间复杂度为 `O(V^2)`，则：

$$
T_{pair}=O(PV^2).
$$

所有机器人-任务对的路径计算为：

$$
O(RM_tPV^2).
$$

最小权二分图匹配的复杂度为：

$$
O(Q^3),\qquad Q=\min(R,M_t).
$$

因此：

$$
\boxed{
T_{total1}=O(RM_tPV^2+Q^3).
}
$$

如果 `P` 被视为建筑结构的常数，则可以简写为：

$$
T_{total1}=O(RM_tV^2+Q^3).
$$

当 `V^2` 远大于 `Q^2` 时，才可以进一步说路径计算项通常占主导。

## 7. 一轮冲突消解的时间复杂度

### 7.1 冲突检测

如果每个机器人路径有至多 `H` 个时空事件，先按资源和开始时间排序，再扫描重叠区间，则冲突检测通常为：

$$
O(RH\log(RH)+X),
$$

其中 `X` 是输出的冲突关系数量。

如果只输出冲突组，不显式输出所有机器人对，则可以把 `X` 视为冲突组数量；如果显式枚举所有两两冲突，最坏可能达到 `O(R^2)`。

### 7.2 当前冲突组的替代路径计算

设当前冲突组大小为 `u_c`。每个冲突机器人检查 `P` 条候选路径，每条路径运行一次 Dijkstra，则：

$$
O(u_cPV^2).
$$

等待代价、路径代价和最大增量的计算为 `O(u_c)`，更新调度表为 `O(u_cH)`。

因此一轮处理一个冲突组的复杂度为：

$$
T_{round}
=O(RH\log(RH)+X+u_cPV^2+u_cH).
$$

用 `u_c<=R` 和 `X<=R^2` 作最宽松上界，可以写成：

$$
T_{round}=O(RH\log(RH)+R^2+RPV^2).
$$

如果电梯冲突只涉及每个机器人一个电梯时间窗，且只输出冲突组，则可将 `R^2` 项降为排序和扫描项；不能无条件写成 `O(R log R)`，因为显式输出所有冲突对时仍可能是 `O(R^2)`。

## 8. 总时间复杂度

冲突消解最多迭代 `K` 轮时：

$$
\boxed{
T_{total2}
=O\left(
K\left(RH\log(RH)+X+RPV^2+RH\right)
\right).
}
$$

使用最坏情况 `X=R^2` 可得：

$$
T_{total2}
=O\left(K(RH\log(RH)+R^2+RPV^2)\right).
$$

总复杂度为：

$$
\boxed{
T_{total}
=O\left(
RM_tPV^2+Q^3
+K(RH\log(RH)+R^2+RPV^2)
\right).
}
$$

如果采用以下额外假设：

- `P`、`H` 为常数；
- 每轮只处理聚合后的冲突组；
- `K<=RP`；
- 冲突组检测不显式枚举全部冲突对；

则可简写为：

$$
T_{total}
=O(RM_tV^2+Q^3+K(R\log R+RPV^2)).
$$

若进一步取 `K=RP`，冲突部分的最坏上界为：

$$
O(PR^2\log R+P^2R^2V^2).
$$

因此不能直接把总复杂度统一写成 `O(RM_tV^2)`，除非已经证明冲突阶段满足

$$
K(RH\log(RH)+R^2+RPV^2)
=O(RM_tV^2).
$$

## 9. 可成立的近似比证明

### 9.1 松弛下界

令 `A_ini` 是忽略机器人间资源冲突后的最优匹配，令

$$
L_0=C_{relax}=\operatorname{cost}(A_{ini}).
$$

因为原问题还要满足电梯、楼梯和窄通道容量约束，所以：

$$
L_0\le OPT.
$$

若初始路径和匹配通过 Dijkstra 与精确最小权匹配求得，则初始阶段的近似比为：

$$
\sigma_1=1.
$$

### 9.2 冲突消解的实例级上界

设算法最终一共改变了 `B` 个机器人路径或等待方案。对第 `i` 个被改变的机器人，定义真实的额外完成时间为：

$$
\delta_i=C_i^{new}-C_i^{old}\ge0.
$$

如果对所有改变的机器人存在统一上界

$$
\delta_i\le\Delta_{max},
$$

则：

$$
ALG
\le
L_0+B\Delta_{max}.
$$

结合 `OPT>=L_0`，得到：

$$
\boxed{
\frac{ALG}{OPT}
\le
1+\frac{B\Delta_{max}}{L_0}.
}
$$

若每个机器人最多改变一次且一个 batch 最多有 `Q` 个已分配任务，则 `B<=Q`，进一步得到：

$$
\boxed{
\sigma
\le
1+\frac{Q\Delta_{max}}{C_{relax}}.
}
$$

这是当前算法可以直接支持的安全的实例级上界。它通常不是与输入规模无关的常数，因为 `C_relax` 可能很小。

### 9.3 用楼梯路径估计 `Delta_max` 的条件

对一个跨 `d` 层的任务，定义：

$$
c_e=h_e+\frac{d}{v_e}+t_e,
$$

$$
c_s=h_s+\frac{d}{v_s}+t_s.
$$

如果满足：

1. 每个冲突机器人都存在可行的楼梯替代路径；
2. 改道后不会产生未计算的新等待；
3. `t_s` 已经包含该机器人真实的楼梯排队等待；
4. `h_s-h_e` 有统一上界 `B_h`；
5. `d<=L-1`；

则：

$$
\delta_i
\le
c_s-c_e
\le
B_h+(L-1)\left(\frac1{v_s}-\frac1{v_e}\right)+(t_s-t_e).
$$

若定义

$$
W_{max}=\max_i(t_s-t_e),
$$

则可取：

$$
\boxed{
\Delta_{max}
=B_h+(L-1)\left(\frac1{v_s}-\frac1{v_e}\right)+W_{max}.
}
$$

注意：`c'_i<=c_i^s` 不是自动成立的，必须把楼梯容量、排队等待和机器人类型约束纳入 `t_s`。

### 9.4 楼梯和电梯的数值模型

PPT 中使用：

$$
t_{stair}(d)=7d,
$$

$$
t_{elevator}(d)=4.5+1.75d.
$$

因此纯垂直段的代价差为：

$$
7d-(4.5+1.75d)=5.25d-4.5.
$$

当 `d>=1` 时为正，说明在不考虑水平接近距离和拥堵时，电梯垂直段更快。并且：

$$
\frac{7d}{4.5+1.75d}<4,
$$

所以楼梯垂直段时间相对于电梯垂直段的比值小于4，极限上趋近4。

但这不能直接推出整条任务路径最多慢4倍，因为两条方案到电梯口、楼梯口和送货点的水平路径可能不同，且电梯等待会改变实际代价。

## 10. 为什么不能直接得到当前 PPT 中的常数近似比

下面三个替换不能用于严格的逐实例近似比：

### 10.1 不能用水平距离上界放大分母

若只有

$$
\sum(l_1+l_2)/v_p\le 2MQ/v_p,
$$

这是分母上界。近似比上界需要分母下界。

### 10.2 不能用 `E[d]` 代替每个实例的 `d`

均匀楼层下：

$$
E[d]=\frac{L^2-1}{3L}
$$

是平均值，但一个具体 batch 可能所有任务都在同一层，导致实际 `sum d_ij=0`。

### 10.3 不能把期望代入比值

一般情况下：

$$
E[ALG/OPT]\ne E[ALG]/E[OPT].
$$

所以均匀楼层假设只能支持平均情形分析，不能自动支持确定性常数近似比。

## 11. 最终建议写法

论文中建议把理论结论写成两层：

### 确定性实例级结论

在每个机器人最多改道一次、所有替代路径可行、每次额外代价不超过 `Delta_max` 的条件下：

$$
ALG\le C_{relax}+Q\Delta_{max},
$$

以及：

$$
\frac{ALG}{OPT}
\le
1+\frac{Q\Delta_{max}}{C_{relax}}.
$$

### 随机平均情形结论

如果取货层和送货层独立均匀分布，则楼梯段 `h` 的跨层流量概率为：

$$
p_h=\frac{2h(L-h)}{L^2}.
$$

中间楼梯段的流量最大。若一个 batch 有 `Q` 个任务、单次楼梯服务时间为 `tau_s`，则该段最后一个机器人的期望等待时间为：

$$
E[W_h^{max}]
=\tau_s\left[Qp_h-1+(1-p_h)^Q\right].
$$

这个结果用于平均等待时间或实验参数估计，不能直接替换确定性近似比中的分母。
