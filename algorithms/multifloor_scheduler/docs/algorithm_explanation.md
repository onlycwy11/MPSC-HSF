# 多层室内机器人集群任务分配算法说明

## 1. 问题与约束

地图是带楼层、平面坐标、边类型和共享资源的有向图。机器人任务类型必须与任务需求类型完全相同；运动类型另用于判断通行能力。一个 batch 内，一个机器人最多执行一个任务，每个任务最多分配给一个机器人。本版本不使用任务优先级，轮式机器人不能走楼梯，只能通过电梯跨楼层。

双向普通边代表宽通道；单向普通边表示窄通道的单行约束，因此普通平面边不按迎面冲突互斥。只有显式设置容量资源的普通边才做时间窗检查。楼梯按“物理楼梯 + 相邻楼层段”区分，只对同一楼层段的反向重叠通行互斥，同向通行允许。电梯每次只搭载一台机器人，整段跨层行程作为一次预约。默认平面速度为 1.5 m/s，楼梯垂直速度为 0.5 m/s，层高为 3.5 m；电梯一次行程为 `4.5 + 1.75 * 跨层数` 秒。

目标是最小化批次完成时间，同时避免共享电梯、对向楼梯通行或显式声明的容量受限资源发生时间窗冲突。输出保留每条路径的节点序列、资源预约表、等待时间和完成时间；预计送达位置与空闲时刻用于更新后续批次的机器人状态。

## 2. 初始路径与分配

对每个机器人—任务对运行带约束的 Dijkstra：跳过机器人不能使用的楼梯边；对电梯边计入登梯时间和楼层运行时间；普通边按长度/速度计时。任务路径由“机器人当前位置→取货点→投递点”两段最短路径拼接而成。对于允许多种垂直方式的机器人，同时保留普通最短路、仅楼梯和仅电梯候选路径。

将可行路径时间放入代价矩阵，使用 Hungarian 算法求最小代价一对一匹配。这个步骤只处理单机器人代价，不把其他机器人尚未确定的时间窗冲突混入矩阵，因此得到的是“忽略冲突的初始解”。不可行的机器人—任务对使用大惩罚值，最终列为未分配任务。

## 3. 冲突检测与处理

沿每条路径累计时间，得到共享资源的占用区间。对同一资源按开始时间排序并进行容量扫描；超过容量的重叠区间形成冲突组。冲突组内，对每个机器人计算两种变化代价：

1. 等待：把该机器人的整条计划向后平移到资源空闲；
2. 换路：切换到不经过当前冲突资源的候选路径，比较额外移动时间。

每个机器人比较等待当前资源与改走其他垂直通道的任务完成时间增量，保留“替代方案增量最大”的机器人当前路线，其余机器人采用各自最快的替代方案。冲突消解期间机器人—任务配对不变。一次冲突组处理结束后，**立即重新扫描全部机器人、全部资源和全部时间窗**，而不是只检查当前冲突组。达到无冲突即停止；若状态重复或超过上限，使用确定性资源串行化兜底。

## 4. 正确性不变量

- 每个计划始终对应一个可行的机器人—任务匹配；候选路径中的边满足机器人运动能力。
- 等待操作只增加开始时间，不改变空间路径，因此不会制造新的前序冲突，但可能影响后续资源；全局重检负责捕获这种影响。
- 换路操作只使用预先验证过的候选路径；全局重检负责验证新路径与所有其他计划的关系。
- 当前 batch 终止时最终冲突集合为空；机器人预计位置和空闲时刻可传给下一批。历史资源预约可通过 JSON 的 `resource_schedule` 或 SQLite 同名表传入，作为固定占用参与新批次规划。

## 5. 复杂度

设机器人数为 R、任务数为 M、图节点数为 V、边数为 E，冲突处理迭代数为 K，每个机器人保留 q 条候选路径。初始代价矩阵需要 O(RM) 次最短路，使用二叉堆 Dijkstra 为 O(RM(E+V)log V)，匹配为 O(max(R,M)^3)。一次全局冲突扫描为 O(qR log(qR))（当前实现的容量扫描为线性排序）。因此总时间可写为

`O(RM(E+V)log V + max(R,M)^3 + K·qR log(qR))`。

K 不是固定的垂直通道数；等待会改变后续时间窗，换路会引入新的资源占用，必须由实际迭代或设置的上限决定。空间复杂度为 O(E+V+qR)。

## 6. 适用边界

当前实现以离散图边和连续时间区间表示资源占用，适合批次级规划。普通地图边按单向/双向拓扑解释通行方向，不推断路口或节点几何碰撞；如需检测交叉口拥堵，应在地图中显式增加节点资源或冲突区资源。
