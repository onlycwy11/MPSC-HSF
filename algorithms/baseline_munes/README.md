# MuNES baseline

对应论文：Donghwi Jung, Chan Kim, Jae-Kyung Cho, Seong-Woo Kim, *MuNES:
Multifloor Navigation Including Elevators and Stairs*, arXiv:2402.04535,
2024。官方代码：<https://github.com/donghwijung/MuNES>（MIT，ROS 包；
`planning/munes_wo_map.py`、`astar.py`、`utils.py`）。

## 论文贡献与本基线的对应关系

MuNES 的算法贡献是**单机器人**多层轨迹规划：电梯/楼梯/走廊统一建图，
A* 边代价显式建模“电梯等待感知”——电梯必须先从当前位置赶到机器人所在
楼层（`calcCost`：`cost = |elv_floor - robot_floor|/elv_speed + 运行时间`，
“come to pick you up”），电梯位置为全局状态、每次规划后更新。**论文不含
任何多机器人机制**（无任务分配、无冲突消解）。

因此本基线按“论文有的层忠实保留、论文没有的层用最朴素机制补齐”的方式
实现，使与主算法的对比能分离出每层真实增益：

| 层 | 我们的算法 | MuNES baseline | 对比度量 |
|---|---|---|---|
| 任务分配 | 匈牙利全局最优 + 类型匹配 | 顺序贪心（按 release 给类型匹配中静态行程最短者） | 分配的增益 |
| 路径规划 | 我们的规划（含次优路径） | MuNES 电梯等待感知寻路（忠实移植） | 寻路代价的增益 |
| 冲突消解 | 换次优路径（等待/换资源/走楼梯） | 只等待（全局 FIFO 先到先执行，不改路径、不换资源） | 冲突消解的增益 |

## 忠实部分（与论文一致的实现）

- **电梯等待感知代价**（`_munes_leg`，对应 `utils.calcCost`）：每条电梯边
  代价 = 赶来等待 `1.75 * |出发层 - 电梯当前层|` + 乘梯 `4.5 + 1.75 * |Δ层|`。
  电梯位置为全局状态，一次规划（一段路径）内固定，规划完成后更新为路径
  终点所在层（论文 `CURR_ELV_FLOOR` 语义）。
- 同一路径中的连续电梯边构成一次不可分割的电梯服务（赶来 + 乘梯全程
  占用电梯）；后规划的机器人必须等前一次服务完全结束（FIFO）。
- 楼梯/走廊边代价与统一物理模型一致（楼梯 3.5·n/0.5 s；平面 length/1.5 s）。

物理参数全部可配置（`SchedulerConfig`，不输入用默认值）。

## 简化部分（论文未覆盖的多机层，写进论文的理由）

论文仅定义单机器人寻路。为将其纳入“多机器人批量调度”对比，多机层采用
最简单机制，避免引入任何可能归因于主算法的智能：

1. **分配 = 顺序贪心**：任务按释放时间排序，逐个交给“类型匹配、静态行程
   （起点→取货→送货）最短”的未分配机器人。无全局优化、无冲突预测。
2. **冲突消解 = 全局 FIFO 等待**：所有机器人按规划顺序使用共享资源
   （电梯、楼梯、单向窄走廊）；后规划者若与已有预约窗重叠，整体顺延等待，
   绝不改路径、不换电梯/楼梯。

## 已验证行为

- 真实 case `A_R1_M1_F8_S17.json`（8 层 L-8F）：makespan 315.25 s，其中
  电梯等待 5.25 s。相比 CBS/TP/Strip 的 301.0 s，多出的 14.25 s 来自 MuNES
  的电梯模型——电梯逐层停靠（3 跳 × 6.25 s vs 一次直达 9.75 s）+ 赶来等待；
  平面路径与三算法完全一致（同为 175 边）。这是模型差异，不是实现误差。
- 双机同起点争唯一电梯：第一台 26.0 s（电梯服务 [0,24]），第二台 45.5 s
  ——电梯等待感知（电梯此时在 3 层，赶来 10.5 s）+ FIFO 顺延 14.25 s，
  两机电梯窗 [0,24] 与 [14.25,43.5] 无重叠。
- 虚拟 6 机（3 层 6×6，1 电梯 1 楼梯）：makespan 32.75 s，无冲突。

## 运行

与主项目同接口：`python run.py --mode virtual --input <config.json>` 或
`python run.py --mode generic --input <case.json>`；`--mode real --map ... --db ...`
走 SQLite 输入。输出 JSON 与主算法同构（assignments / metrics / path）。
